Zajil for Android

The file is on the Android releases page on GitHub.

The app

The same download engine as on the computer: downloads in parts, resuming after the network drops, queues and videos. With a browser that finds the video on a page and blocks ads and harmful sites.

  • Android

    Android 8 or later, on phones with a 64-bit processor (arm64-v8a), which most recent phones have. The app looks for its new version itself, and installs only one signed with the project's key.

    Download for Android .apk

  • What it does not do

    No ads, no analytics, no device ID, no account. It connects only to the sites you download from, and to GitHub for the update check and the signed protection lists. Every check for harmful sites happens on your phone.

Zajil is not on Google Play yet, so Android asks for your permission before installing it, and Play Protect may warn you because it is a new app from outside the store. This is expected; the steps are under “Installing” below.

Installing

Button names differ a little between phones and languages.

1. Allow installing from the browser

  1. Open the file once it has downloaded, from the browser's notification or from the Files app.
  2. Android says this source is not allowed to install apps: tap Settings.
  3. Turn on Allow from this source, then go back.
  4. Tap Install. You can turn the permission off again afterwards.

2. The Play Protect warning

  1. If a message says Play Protect does not know this app, or has blocked it, tap More details.
  2. Tap Install anyway.
  3. If it asks to send the app to Google for a scan, that is your choice; it installs either way.

Why does Play Protect warn? Because it does not know new apps from outside Google Play. What proves the file is ours is its checksum and its signature: all the code is on GitHub, and the file is built on GitHub only. How to check is under “Checking the file”.

Checking the file

The file's checksum: download SHA256SUMS-android from the release page into the same folder as the file, then run on a computer:

Mac

shasum -a 256 -c SHA256SUMS-android --ignore-missing

Linux

sha256sum -c SHA256SUMS-android --ignore-missing

Windows (PowerShell)

$f = Get-Item .\zajil-android-*-arm64-v8a.apk
(Get-FileHash $f).Hash -eq (Select-String -SimpleMatch $f.Name .\SHA256SUMS-android).Line.Split(' ')[0]

The line must end in OK, or Windows must print True.

The app's signature: every version of Zajil for Android is signed with one key, and Android refuses an update signed with another. Its certificate's fingerprint (SHA-256):

22:09:58:0E:C2:9E:F4:9A:F1:E0:81:82:22:9F:10:0B:E2:18:16:0D:AD:7C:D9:38:84:BB:D7:0C:D9:E1:C9:E0

Read it from the file with apksigner, from Android's developer tools:

apksigner verify --print-certs zajil-android-*-arm64-v8a.apk

The SHA-256 digest line must match the fingerprint above (without the colons, in lower case). If it does not, do not install the file, and tell us on GitHub.

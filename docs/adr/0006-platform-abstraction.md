# ADR-0006: الأنظمة الثلاثة — واجهة واحدة وثلاثة تنفيذات

| البند | القيمة |
|---|---|
| الحالة | **مقبول** (مطلب من المالك) |
| التاريخ | 2026-10-23 |
| صاحب القرار | Motalim (@motalim-ai) |

## السياق
زاجِل مصمم من أول يوم لويندوز وماك ولينكس. **لا يُقبل أي حل يعمل على نظام واحد فقط.** وبعض الأجزاء تختلف بالضرورة بين الأنظمة.

## القرار
مكتبة **`zajil-platform`** تعرّف واجهات (Rust traits)، ولكل واجهة تنفيذ لكل نظام، يُختار وقت البناء (`#[cfg(target_os = …)]`).

| الواجهة | الوظيفة |
|---|---|
| `NativeHostRegistrar` | تسجيل مضيف Native Messaging وإلغاء تسجيله لكل متصفح مدعوم |
| `Clipboard` | قراءة الروابط من الحافظة ومراقبتها |
| `Notifier` | إشعارات النظام |
| `Autostart` | التشغيل مع بدء النظام |
| `AppPaths` | مسارات الإعدادات والبيانات والسجلات ومجلد التحميل الافتراضي |
| `PowerControl` | إيقاف الجهاز أو إدخاله في السكون بعد الانتهاء، ومنع السكون أثناء التحميل |
| `LocalIpc` | قناة الاتصال المحلية الخاصة بالمستخدم |

## القواعد
1. **ممنوع** وضع `cfg(target_os)` خارج `zajil-platform`، إلا لاستثناء موثق ومراجَع.
2. **كل واجهة لها ثلاثة تنفيذات قبل الدمج.** لا يُقبل تنفيذ واحد مع وعد بالباقي لاحقًا.
3. **كل تنفيذ له اختبارات** تعمل في الـ CI على نظامه. وما لا يمكن اختباره آليًا (مثل إيقاف الجهاز) يُختبر بتنفيذ وهمي (mock) آليًا، ثم يدويًا قبل الإصدار.
4. **المثبّتات** لكل نظام تُبنى في الـ CI:
   - ويندوز: ‎.exe أو ‎.msi.
   - ماك: ‎.dmg.
   - لينكس: AppImage و‎.deb.
5. **الـ CI يبني ويختبر على الأنظمة الثلاثة في كل Pull Request** ابتداءً من M0.

## العواقب
- العمل أبطأ قليلًا لكل ميزة، لكنه يمنع أن يصبح نظام ما «مواطنًا من الدرجة الثانية».
- **الـ arm64**: نبني لها ابتداءً من M8. والـ CI يختبر على المعماريات التي تتيحها GitHub Actions، ويُحدد ذلك في M8.

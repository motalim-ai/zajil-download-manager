# ADR-0004: تنسيق ملف الحالة

| البند | القيمة |
|---|---|
| الحالة | **مقبول** (وافق المالك في 2026-10-23) |
| التاريخ | 2026-10-23. حُدِّث في M1 بقرار المالك: البصمة SHA-256 بدل CRC32C |
| صاحب القرار | Motalim (@motalim-ai) |

## السياق

لكي نستكمل التحميل بعد الانقطاع، نحتاج أن نحفظ: الرابط، وحجم الملف، ومعرّف نسخته على السيرفر (`ETag` أو `Last-Modified`)، وما اكتمل من كل جزء. ويجب أن:

- **يتحمل انقطاع الكهرباء** أثناء الكتابة دون أن يفسد.
- **لا يدّعي أبدًا** أن بيانات اكتملت وهي لم تُكتب على القرص فعلًا.
- يعمل مع **المحرّك وحده** (سطر الأوامر دون الواجهة الرسومية).
- يمكن **تطويره** لاحقًا دون أن تفشل التحميلات القديمة.

هذا الملف خاص **بكل تحميل** على حدة. أما قوائم الانتظار والإعدادات والسجل فلها قرار منفصل في بداية M3.

## الخيارات
| الخيار | المزايا | العيوب |
|---|---|---|
| **ملف JSON بجانب الملف الجزئي** | سهل القراءة والتصحيح، ويعمل مع سطر الأوامر دون قاعدة بيانات، ويُنقل مع الملف | كتابة الملف كاملًا في كل تحديث. الحجم صغير (بضعة كيلوبايت حتى مع 32 جزءًا) |
| SQLite مركزية لكل التحميلات | معاملات آمنة (transactions) جاهزة، ومناسبة للقوائم والسجل | تربط المحرّك بقاعدة بيانات مركزية، ولا تُنقل مع الملف، وفساد القاعدة يضر كل التحميلات |
| تنسيق ثنائي خاص (binary) | صغير وسريع | صعب التصحيح والتطوير، ويحتاج كود قراءة وكتابة خاصًا |
| حفظ الحالة داخل الملف الجزئي نفسه | ملف واحد | يعقّد الإنهاء ويخلط البيانات بالحالة |

## القرار

لكل تحميل ملفان في مجلد التحميل:
- `<الاسم>.zajil-part`: البيانات، وتُحجز مساحتها مسبقًا إن كان الحجم معروفًا.
- `<الاسم>.zajil-state`: الحالة بصيغة **JSON** وترميز UTF-8.

مثال (للتوضيح فقط. المخطط النهائي حُدد في M1، وهو في [docs/STATE-FILE.md](../STATE-FILE.md)):

```json
{
  "format": "zajil-state",
  "schema_version": 1,
  "url": "https://example.com/file.zip",
  "final_url": "https://cdn.example.com/file.zip",
  "validator": { "etag": "\"abc123\"", "last_modified": "Wed, 21 Oct 2026 07:28:00 GMT" },
  "content_length": 104857600,
  "accept_ranges": true,
  "segments": [
    { "start": 0,        "end": 52428799,  "done": 31457280 },
    { "start": 52428800, "end": 104857599, "done": 10485760 }
  ],
  "created_at": "2026-10-23T10:00:00Z",
  "updated_at": "2026-10-23T10:05:12Z",
  "checksum": "sha256:…"
}
```

### قواعد الكتابة الآمنة
1. **البيانات أولًا**: تُكتب البيانات في `.zajil-part`، ثم تُثبَّت على القرص (`fsync`)، **ثم** يُحدَّث ملف الحالة.
2. **تحديث ملف الحالة في خطوة واحدة**: نكتب ملفًا مؤقتًا، ثم `fsync`، ثم إعادة تسمية فوق الملف القديم. وفي ماك ولينكس يُثبَّت المجلد أيضًا (`fsync`).
3. **حقل `checksum`** يكشف إذا كان الملف قد فسد. إذا فسد ملف الحالة، يُعامل التحميل كأنه لا يمكن استكماله ويبدأ من جديد. ولا نخمّن أبدًا.
4. **تكرار الحفظ محدود**: مثلًا كل ثانية، أو عند الإيقاف المؤقت، أو عند انتهاء جزء. هذا يحمي الأقراص من الكتابة المفرطة. (منذ #132: الإيقاف لا يحفظ إن كان حفظ دوري قد نجح، لأن ملف الحالة يعدّ ما زُومِن فقط.)
5. **قفل الملف (file lock)**: يمنع عمليتين (مثل سطر الأوامر والواجهة) من العمل على نفس التحميل في نفس الوقت.
6. **`schema_version`**: عند تغيير المخطط نكتب تحويلًا من النسخة القديمة، ونختبره.
7. **لا أسرار في ملف الحالة**: لا نحفظ الكوكيز ولا ترويسات التوثيق فيه. إن احتجنا حفظها لاستكمال التحميل، فمكانها مخزن آمن خاص بكل نظام، ولهذا قرار منفصل في M5. **وقرار المالك على #7 (2026-10-25): الكوكيز في الذاكرة فقط، لا على القرص.** أما ترويسات التوثيق وبيانات الدخول فلم يُقرر مكانها بعد.

### البصمة: SHA-256 وليس CRC32C (حُسم في M1)
كان المثال الأول في هذه الورقة يذكر `crc32c`. وعند التنفيذ في M1 اخترنا **SHA-256**، ووافق المالك على ذلك (2026-10-23):
- **مكتبة واحدة بدل اثنتين**: المحرّك يحتاج `sha2` أصلًا لبصمات الملفات المحمّلة، فـ CRC32C كان سيضيف مكتبة ثانية دون فائدة.
- **السرعة لا تهم هنا**: ملف الحالة صغير (بضعة كيلوبايت)، ويُحفظ مرة في الثانية على الأكثر.
- **كشف أقوى**: SHA-256 يكشف أي تعديل، لا الأخطاء العشوائية فقط. وهذا ليس توقيعًا، فالغرض كشف الفساد وليس منع التلاعب المتعمد.

الصيغة: `sha256:` ثم البصمة بالـ hex لتمثيل JSON المضغوط للحالة مع `checksum` فارغ. التفاصيل في [docs/STATE-FILE.md](../STATE-FILE.md).

## العواقب
- يمكن نسخ مجلد تحميل غير مكتمل إلى جهاز آخر واستكماله هناك، إذا كان الرابط ما زال صالحًا.
- مجلد التحميل يحتوي ملفين إضافيين أثناء التحميل. يحذفهما البرنامج عند الانتهاء، ويمكن إخفاؤهما في الواجهة.
- قوائم الانتظار والإعدادات (M3) سيُقرر تخزينها لاحقًا. SQLite مرشح قوي هناك، لكن **لا يعتمد المحرّك عليها للاستكمال**.

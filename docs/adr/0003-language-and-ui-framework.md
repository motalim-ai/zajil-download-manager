# ADR-0003: لغة البرمجة وإطار الواجهة

| البند | القيمة |
|---|---|
| الحالة | **مقبول** (وافق المالك في 2026-10-23) |
| التاريخ | 2026-10-23 |
| صاحب القرار | Motalim (@motalim-ai) |

## السياق

نحتاج لغة للمحرّك وسطر الأوامر ومضيف Native Messaging، وإطارًا للواجهة الرسومية. وهذه الشروط **إلزامية**:

1. **الأنظمة الثلاثة** (ويندوز وماك ولينكس) على x86_64 وarm64.
2. **العربية من اليمين إلى اليسار بجودة عالية**. وهذا يشمل:
   - تشكيل الحروف العربية ووصلها (text shaping).
   - خوارزمية اتجاه النص (Unicode Bidi)، عندما يجتمع نص عربي مع أسماء ملفات وروابط إنجليزية.
   - قلب اتجاه الواجهة بالكامل (mirroring).
   - صيغ الجمع العربية الست.
3. **الأمان**: المحرّك يعالج بيانات من الإنترنت لا نثق بها (ترويسات HTTP، وأسماء ملفات، ورسائل من الإضافة)، فنريد لغة تمنع أخطاء الذاكرة.
4. **الحجم والأداء**: البرنامج يعمل في الخلفية طوال الوقت، فيجب أن يكون خفيفًا.
5. **توافق الترخيص** مع GPL-3.0.
6. **مضيف Native Messaging** يجب أن يكون ملفًا تنفيذيًا صغيرًا يبدأ بسرعة.

## الخيارات

### لغة المحرّك
| الخيار | المزايا | العيوب |
|---|---|---|
| **Rust** | أمان الذاكرة دون جامع قمامة، وأداء عالٍ، وملف تنفيذي واحد صغير. ومكتبات async ناضجة: tokio وhyper/reqwest وrustls | منحنى تعلّم أعلى، ووقت بناء أطول |
| Go | بسيطة، وأداء جيد، وبناء سريع | ملف تنفيذي أكبر، وجامع قمامة. وخيارات الواجهة الرسومية فيها محدودة (Wails) |
| C++ | أداء أقصى، وQt متاح | لا تحمي من أخطاء الذاكرة، وهذا خطر حقيقي مع بيانات الإنترنت |
| C# / .NET | إنتاجية عالية، وAvalonia متاح | runtime أكبر، والتجميع المسبق (Native AOT) له قيود |
| TypeScript / Node | أسهل للمساهمين | استهلاك ذاكرة أعلى، وليست مناسبة لمضيف صغير سريع البدء |

## القرار

- **Rust** للمحرّك (`zajil-core`)، وسطر الأوامر (`zajil`)، والمضيف (`zajil-host`)، والطبقة الخاصة بكل نظام (`zajil-platform`).
- **Tauri 2** للواجهة الرسومية. تُكتب الواجهة بـ **TypeScript** وHTML وCSS. **مكتبة الواجهة** (Svelte أو Solid أو React أو مكونات ويب بلا مكتبة) تُختار في ADR مستقل في بداية M4.
- **الترجمة والجمع**: نظام **Fluent** من Mozilla (مكتبة `fluent` في Rust ومقابلها في JS). صُمم ليدعم صيغ الجمع العربية الست (zero/one/two/few/many/other)، ويسمح للمترجم بالتحكم في صياغة الجملة.

## السبب

1. **العربية**: محرّك الويب هو أنضج مكان لعرض النص العربي المختلط بالإنجليزية على الأنظمة الثلاثة. القوائم والجداول وأسماء الملفات الطويلة تُعرض صحيحة دون عمل خاص.
2. **الأمان**: Rust تمنع فئة كاملة من الثغرات (أخطاء الذاكرة) في الجزء الذي يتعامل مع الإنترنت. وTLS عبر **rustls** مع مخزن شهادات النظام (`rustls-platform-verifier`) يعطي تحققًا واحدًا متسقًا على الأنظمة الثلاثة.
3. **لغة واحدة لكل ما ليس واجهة**: المحرّك وسطر الأوامر والمضيف كلها Rust، دون جسور بين لغات.
4. **الحجم**: Tauri يستخدم محرّك الويب الموجود في النظام، فيبقى المثبّت صغيرًا مقارنة بـ Electron.
5. **الإصدار**: أدوات Tauri تنتج المثبّتات الخمسة المطلوبة في M8 من نفس الـ CI.
6. **الترخيص**: Rust وTauri وtokio وreqwest وrustls كلها بتراخيص MIT أو Apache-2.0 (أو ما يشبهها)، وكلها متوافقة مع GPL-3.0. وWebKitGTK بترخيص LGPL ويُربط ديناميكيًا.

## العواقب والمخاطر

| الخطر | التعامل معه |
|---|---|
| ثلاثة محركات ويب مختلفة، والواجهة قد تظهر بشكل مختلف قليلًا على كل نظام | نستخدم ميزات CSS الثابتة فقط، ونلتقط صورًا للواجهة على الأنظمة الثلاثة في الـ CI ابتداءً من M4، ونختبرها يدويًا قبل كل إصدار |
| WebKitGTK على لينكس يختلف إصداره بين التوزيعات | نحدد الحد الأدنى للتوزيعات المدعومة في M4. وAppImage يقلل المشكلة |
| أدوات الاختبار الآلي للواجهة (WebDriver) لا تدعم ماك بالكامل حسب آخر ما نعرف | **يحتاج تحقق في M4**. البديل: اختبارات منطق الواجهة دون نافذة، ثم اختبار يدوي على ماك |
| Rust أصعب على المساهمين الجدد | وثائق واضحة، واختبارات تعمل بأمر واحد، ومسائل مناسبة للمبتدئين (good first issue) |
| المحرّك والواجهة بلغتين (Rust وTypeScript) | واجهة أوامر وأحداث محددة بين الطرفين، مع أنواع بيانات تُولَّد تلقائيًا حتى لا يختلف الطرفان |

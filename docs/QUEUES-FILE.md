# مواصفات ملف القوائم `queues.json` (المخطط v1)

| البند | القيمة |
|---|---|
| الحالة | مُطبَّق في M3، ومعه في M4 الحقل `categorize` وملف التصدير، وفي M5.5 الحقول `name` و`category` و`description` و`last_try` (#95، #103) |
| القرار | [ADR-0007](adr/0007-queues-and-settings-storage.md) |
| الكود | `crates/zajil-core/src/queue/store.rs` |

## المكان

في مجلد البيانات: `AppPaths::data_dir()`، أو المجلد الذي يحدده `zajil --data-dir`. ومعه ملفان:
- `queues.lock`: قفل تأخذه كل عملية تعدّل الملف.
- `runner.lock`: قفل يأخذه `zajil queue run` طوال عمله.

| `schema_version` | عدد | دائمًا `1` في هذا المخطط |
| `next_id` | عدد | الرقم الذي يأخذه التحميل التالي. الأرقام لا تُعاد أبدًا |
| `settings.speed_limit` | عدد أو `null` | حد السرعة للبرنامج كله، بالبايت في الثانية (أكبر من 0). `null` أو غيابه: بلا حد |

| `schedule.days` | قائمة | الأيام التي تبدأ فيها النافذة: `mon` و`tue` و`wed` و`thu` و`fri` و`sat` و`sun`. فارغة: كل يوم |
| `queues[].items` | قائمة | تحميلاتها بالترتيب |
| `items[].id` | عدد | رقم التحميل، فريد، وأصغر من `next_id` |
| `items[].url` | نص | الرابط، **بلا اسم مستخدم ولا كلمة مرور** (لا يُضاف رابط فيه أحدهما). وقد يحمل توكنًا (`?sig=…`)، ولا يُطبع معه أبدًا |
| `items[].dir` | نص | مجلد الحفظ، مسار مطلق |
| `items[].status` | نص | `waiting`، أو `active`، أو `paused`، أو `done`، أو `failed` |
| `items[].state_file` | نص أو `null` | ملف `.zajil-state` الخاص بالتحميل، بعد أن يبدأ. **التقدم فيه** (ADR-0004). يُمسح إذا توقف التحميل أو فشل قبل أول بايت (تُحذف ملفاته، وقد يأخذ اسمه تحميل آخر). ولا يُستكمل إلا إذا كان `url` فيه هو رابط العنصر نفسه، وإلا يبدأ تحميل جديد (مراجعة #31) |
| `items[].file` | نص أو `null` | الملف المكتمل |
| `items[].error` | نص أو `null` | سبب الفشل أو التوقف |
| `items[].limit` | عدد أو `null` | حد السرعة لهذا التحميل وحده، بالبايت في الثانية (أكبر من 0). وحد البرنامج يبقى. `null` أو غيابه: بلا حد خاص. وتغييره يصل إلى التحميل الشغال عند نظرة المشغّل التالية، دون أن يتوقف (#106) |
| `items[].categorize` | منطقي، اختياري | (M4) أُضيف دون مجلد خاص به (`zajil queue add` دون `--dir`، أو مع `--by-category`): الملف المكتمل يذهب إلى مجلد فئته ([CATEGORIES-FILE](CATEGORIES-FILE.md))، وإلى `dir` إذا لم يكن لفئته مجلد. غيابه يعني `false`. أُضيف إلى المخطط v1 قبل نشره، كما أُضيف `had_credentials` إلى ملف الحالة |
| `items[].needs_ok` | منطقي، اختياري | (مراجعة الأمان #84) ملف قد يشغّل برامج جاء من إضافة المتصفح: ينتظر أن يبدأه المستخدم، ويُمسح حين يبدأ. غيابه يعني `false` |
| `items[].from_page` | منطقي، اختياري | (مراجعة #90) جاء من صفحة (إضافة المتصفح): يُوقف إن سمّى السيرفر عند التحميل نفسه ملفًا قد يشغّل برامج، ما لم يكن المستخدم قد بدأه. غيابه يعني `false` |
| `items[].ok_given` | منطقي، اختياري | (مراجعة #90) بدأه المستخدم وهو موقوف: لا يُوقف مرة أخرى. غيابه يعني `false` |
| `items[].private` | منطقي، اختياري | (مراجعة الأمان #84) جاء من نافذة خاصة: يُؤخذ من القوائم حين يكتمل، فلا يبقى منه إلا الملف. غيابه يعني `false` |
| `items[].added_at` | نص | وقت الإضافة بصيغة RFC 3339 بتوقيت UTC |
| `items[].browser` | كائن، اختياري | (M5) جاء من إضافة المتصفح: `instance` (معرّف الإضافة العشوائي، واحد لكل ملف شخصي في المتصفح)، و`store` (مخزن الكوكيز، حاوية Firefox، إن لم يكن الافتراضي)، و`cookies` (هل ذهبت معه كوكيز)، و`referrer` (الصفحة التي جاء منها، بلا الجزء بعد `#`، ولا تُطبع في أي سجل أو رسالة)، و`ticket` (تذكرة التحميل العشوائية من الإضافة). **الكوكيز نفسها لا تُكتب هنا أبدًا** (قرار المالك على #7): بعد إعادة التشغيل يطلبها زاجِل من نفس المتصفح. ويُحذف حين يكتمل التحميل. أُضيف إلى المخطط v1 قبل نشره، كما أُضيف `categorize` |
| `items[].name` | نص، اختياري | (M5.5، #103) اسم الملف الذي اختاره المستخدم: يُحفظ التحميل الجديد به بدل اسم السيرفر. يُنظَّف كأي اسم ملف (`sanitize_file_name`)، ويُرقَّم كأي اسم إذا كان مأخوذًا، ويُرفض الاسم الذي لا يبقى منه شيء بعد التنظيف (مثل `.`). لا يتغير بعد أن يبدأ التحميل (`state_file` أو `file`، أو الحالة `active` أو `done`)، لأن الملف أخذ اسمه. وإذا كان الاسم الجديد لملف قد يشغّل برامج (`RUNS_CODE`) واسم السيرفر لا، يُوقف التحميل قبل أن يُنشأ أي ملف، كما في #90، حتى يبدأه المستخدم. وتغيير الاسم يمسح `ok_given`. والتحميل من صفحة (`from_page`) يُوقف بالاسم الذي يُحفظ به. غيابه: اسم السيرفر |
| `items[].category` | نص، اختياري | (M5.5، #103) معرّف الفئة التي اختارها المستخدم ([CATEGORIES-FILE](CATEGORIES-FILE.md))، بدل الفئة التي يعطيها الاسم أو الموقع. التحميل الذي أُضيف دون مجلد خاص به (`categorize`) يذهب إلى مجلدها، أيًّا كان اسمه أو موقعه، وإلى `dir` إذا لم يكن لها مجلد. أما التحميل الذي اختار له المستخدم مجلدًا، فيبقى في مجلده، والفئة تسمية فقط (والواجهة التي تريد مجلد الفئة تضعه في `dir`). والفئة المحذوفة كأنها غير موجودة. والملف الذي أُنشئ لا يُنقل. غيابه: الفئة من الاسم أو الموقع كما في M4 |
| `items[].description` | نص، اختياري | (M5.5، #95) وصف يكتبه المستخدم: من 1 إلى 1000 حرف، أسطر يفصلها `\n` فقط، بلا رموز تحكم ولا نص خفي (نفس فحص أسماء القوائم، سطرًا سطرًا) |
| `items[].last_try` | نص، اختياري | (M5.5، #95) وقت آخر بداية أو استكمال بصيغة RFC 3339 بتوقيت UTC، يكتبه المشغّل حين يعلّم العنصر `active`. لا يُصدَّر |
| `updated_at` | نص | وقت آخر تعديل |
| `checksum` | نص | `sha256:` ثم البصمة، بنفس الصيغة القانونية التي يستعملها ملف الحالة ([STATE-FILE](STATE-FILE.md#البصمة-والصيغة-القانونية)) |

## قواعد القراءة

يُرفض الملف، **ولا يُكتب فوقه**، إذا:
- كان رابطًا رمزيًا أو رابطًا صلبًا أو غير ملف عادي.
- كان أكبر من 16 ميجابايت.
- لم يكن JSON صالحًا، أو كان `format` غيره، أو `schema_version` غير مدعوم.
- احتوى حقلًا غير معروف، أو لم تطابق البصمة.
- كان فيه رقم مكرر أو أكبر من `next_id`، أو اسم قائمة مكرر أو غير صالح، أو `max_active` خارج حدوده، أو حد سرعة يساوي 0.
- كان فيه `name` فارغ أو أطول من 200 بايت أو فيه فاصل مسار أو رمز تحكم، أو كان `.` أو `..`، أو `category` ليس معرّف فئة، أو `description` يرفضه فحصه، أو `last_try` ليس وقتًا بصيغة RFC 3339 بتوقيت UTC. وفحص `name` هنا لا يعتمد على قواعد التنظيف، حتى لا يصبح الملف كله تالفًا إذا تغيّرت تلك القواعد. والمحرّك ينظّف الاسم من جديد عند استعماله.

والملف غير الموجود يعني قائمة `main` فارغة.

## قواعد الكتابة

- **كل تعديل يمر عبر `QueueStore::update`**: يأخذ `queues.lock`، ثم يقرأ الملف ويتحقق منه، ثم يعدّل، ثم يكتب، ثم يحرر القفل. فلا يضيع تعديل عمليتين في نفس الوقت.
- **الكتابة** بنفس قواعد ملف الحالة: ملف مؤقت (`queues.json.tmp`) لا يقرؤه إلا صاحبه، يُنشأ دون أن يتبع أي رابط، ثم `fsync`، ثم إعادة تسمية فوق القديم، ثم `fsync` للمجلد. وفي ماك نفس النافذة الصغيرة المعروفة قبل حذف قائمة الصلاحيات الموروثة ([STATE-FILE](STATE-FILE.md#قواعد-الكتابة)، القاعدة 0).
- **القراءة دون قفل**: القارئ يرى الملف القديم أو الجديد. وإذا فتح القديم في اللحظة التي استُبدل فيها، فعدد روابطه يصبح 0. هذا مقبول، لأنه ليس رابطًا صلبًا (وجدته اختبارات الـ CLI: كانت القراءة تُرفض).

## ملف التصدير (M4)

`zajil queue export <ملف>` يكتب القوائم في ملف بصيغة مستقلة، و`zajil queue import <ملف>` يضيفها. بقرار المالك على #36 (النقل إلى M4)، وشرط نجاحه على خطة M4 (#6).

| الحقل | المعنى |
|---|---|
| `format` | دائمًا `"zajil-queues-export"` |
| `schema_version` | دائمًا `1` |
| `settings.speed_limit` | حد البرنامج، كما في `queues.json` |
| `queues[]` | `name` و`max_active` و`schedule`، كما في `queues.json` |
| `queues[].items[]` | `url` و`dir` و`limit` و`categorize` و`added_at`، و`status`: `waiting` أو `paused` أو `done`. التحميل الجاري أو الفاشل يُصدَّر `waiting`، فيعمل من جديد في الطرف الآخر. ومعها ما أعطاه المستخدم (M5.5): `name` و`category` و`description`، اختيارية، وتُفحص عند الاستيراد بنفس القواعد. أما `last_try` فلا يُصدَّر |
| `exported_at` | وقت التصدير |
| `checksum` | بنفس الصيغة القانونية |

**ما لا يُصدَّر**: الأرقام، والتقدم (`state_file`)، والملف المكتمل، والخطأ. هذه كلها تخص هذا الجهاز.

**الأمان**:
- **لا اسم مستخدم ولا كلمة مرور أبدًا**: القوائم لا تحملهما أصلًا، والتصدير يحذفهما لو ظهرا، والاستيراد يرفض ملفًا فيه أحدهما.
- **التوكن الذي هو جزء من الرابط** (`?sig=…`) يبقى، بشرطي AGENTS.md §10.3: الملف لا يقرؤه إلا صاحبه، والتوكن لا يُطبع أبدًا. مختبر.
- **تنبيه** (بقرار المالك على #41): الملف فيه الروابط كما هي، وبعضها قد يحمل مفاتيح دخول مؤقتة. **لا تنشره.** و`zajil queue export` يطبع هذا التنبيه بعد كل تصدير، دون أي رابط.
- **لا ترويسات أبدًا**: لا `Cookie` ولا `Authorization` ولا غيرهما. زاجِل لا يحفظ ترويسات في القوائم أصلًا، والملف لا يعرف إلا الحقول المذكورة أعلاه، والقراءة الصارمة ترفض أي حقل آخر. مختبر.
- **لا يُكتب فوق ملف موجود**، ولا عبر رابط رمزي، ولا يُحذف شيء: الملف يُكتب في ملف مؤقت باسم خاص به، ثم يأخذ اسمه بإعادة تسمية لا تستبدل.
- **الملف عند الاستيراد مُدخل غير موثوق**:
  - حد للحجم (16 ميجابايت).
  - قراءة صارمة: الحقل غير المعروف يُرفض، والبصمة يجب أن تطابق.
  - كل قيمة تُفحص قبل أي تعديل: الأسماء، و`max_active`، والروابط (http وhttps فقط، وبلا بيانات دخول ولا رموز تحكم ولا علامات اتجاه ولا فواصل أسطر، بنفس قاعدة `zajil queue add`، فيستورد زاجِل كل ما يصدّره)، والجدولة (كما يصنعها زاجِل: غير فارغة، وكل يوم مرة واحدة وبالترتيب)، والأوقات (RFC 3339)، وحدود السرعة.
  - **ولا يُكتب أبدًا ملف قوائم أكبر من أن يقرأه زاجِل** (16 ميجابايت): التعديل الذي يتجاوز ذلك يُرفض كله، فلا تضيع القوائم الموجودة (مراجعة #41). وكذلك ملف الفئات (1 ميجابايت).
  - **المجلدات تُفحص فقط مع `--keep-folders`**: مسار مطلق عادي، بلا `..`، ونص صالح بلا رموز تحكم ولا رموز خفية: رموز التنسيق مثل U+202E، وكل رمز يُتجاهل افتراضيًا (Default_Ignorable) مثل U+3164. **ويُسمح** بالرابطين ZWNJ وZWJ وبمحددات الشكل (variation selectors)، لأنها جزء من نص حقيقي: الإيموجي مثل ❤️، والفارسية، والأشكال الصينية واليابانية (رموز الهروب كانت تصل إلى الطرفية: الجولة الثانية من المراجعة)، وفي ويندوز مسار على قرص فقط، لا مسار شبكة (`\\server\share`) ولا مسار جهاز (`\\?\`). فالتصدير من نظام آخر يُستورد في مجلد المستخدم دون مشكلة.
  - الملف المرفوض لا يغيّر شيئًا، والرسالة تقول السبب.
- **المجلدات في الملف لا تُستعمل إلا بطلب**: بدون `--keep-folders`، تذهب التحميلات إلى `--dir` (أو مجلد التنزيلات في النظام) ومجلدات فئاتها. السبب: ملف من شخص آخر قد يوجّه التحميلات إلى أي مجلد، مثل مجلد التشغيل مع بدء النظام.

**الدمج**: القائمة الجديدة تُنشأ بإعدادات الملف. والقائمة التي لم يمسها أحد (فارغة وبالإعدادات الافتراضية، مثل `main` في مجلد بيانات جديد) تأخذ إعدادات الملف. والقائمة الموجودة غير ذلك تبقى إعداداتها، وتُضاف التحميلات إلى آخرها، ويذكر `zajil` اسمها. وحد البرنامج في الملف لا يُستعمل إلا إذا لم يكن هناك حد.

## المشغّل (`zajil queue run`)

- **حالة `active` يتركها مشغّل قُتل** تعود إلى `waiting` عند التشغيل التالي، ويُستكمل التحميل من `state_file`.
- **الإيقاف المؤقت والحذف**: يغيّر المستخدم الحالة في الملف، فيوقف المشغّل التحميل بطريقة «أوقف وانتظر» (`Stop`): يُسجَّل ما على القرص، ثم يُكتب الوضع الجديد بعد أن يتوقف كل شيء.
- **الجدولة**: خارج نافذة القائمة لا يبدأ شيء منها، وتحميلاتها الجارية تتوقف بطريقة «أوقف وانتظر» وتعود إلى `waiting`، ثم تُستكمل في النافذة التالية. والمشغّل لا ينتهي ما دام في قائمة مجدولة تحميل ينتظر، بل ينام حتى تفتح.
- **حد معروف**: إذا قُتل المشغّل بعد أن ينشئ التحميل ملفاته وقبل أن يُسجَّل `state_file` (أجزاء من الثانية)، يبدأ التشغيل التالي التحميل من جديد باسم مرقّم، ويبقى الملفان القديمان.

## English summary

`queues.json` in the data folder (schema v1): `format` (`zajil-queues`), `schema_version`, `next_id`, `settings {speed_limit}`, `queues [{name, max_active, schedule {start, stop, days}, items [{id, url, dir, status, state_file, file, error, limit, categorize, needs_ok, from_page, ok_given, private, added_at, browser {instance, store, cookies, referrer, ticket}}]}]`, `updated_at`, `checksum` (same canonical SHA-256 as the state file). Every change goes through `QueueStore::update`, holding `queues.lock` from read to write; `runner.lock` allows one `zajil queue run`. Writes are safe (temporary file readable by the user only, fsync, rename, folder sync); a damaged file is refused and never overwritten. URLs never hold a user name or password; a token in a URL is kept but never printed. A download's progress stays in its `.zajil-state` file. M4: `categorize` (optional) sends an item to its category's folder; `zajil queue export`/`import` use a separate `zajil-queues-export` file (no ids, progress or credentials, owner-only, never written over; imports are strictly checked and use the file's folders only with `--keep-folders`). An item's `limit` reaches its running download at the runner's next look, without a stop (#106). M5: `browser` (optional) says which extension instance and cookie store a download came from, whether cookies went with it, its page (without its `#` part, never printed) and its ticket; never the cookies themselves; removed when it is done; not exported. M5.5 (#95, #103), all optional: `name` (the user's file name, cleaned like any name, used instead of the server's; fixed once the download starts; held like #90 when it can run code and the server's name could not), `category` (a category id chosen by the user: a download added without a folder of its own goes to its folder; with a folder the user chose it is a label; a removed category counts as none; a made file does not move), `description` (1 to 1000 characters, `\n`-separated lines without hidden text), `last_try` (RFC 3339 UTC, written by the runner when it marks the item active). The first three are exported and checked on import; `last_try` is not exported.
